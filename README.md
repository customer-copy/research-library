# Research Library
A native, local-first macOS research archive with an iPhone/iPad capture companion. Articles do not require PDFs. Your archive is ordinary JSON and attachment files, independent of this application.

## Run locally
A verified local macOS copy is installed at `~/Applications/Research Library.app`. Open that app in Finder, choose **Select Library**, and select or create a folder. The project also contains `Build/Research Library.app`. iCloud can reattach Finder metadata to bundles inside the workspace; use the local Applications copy for reliable signing and launch. An iCloud Drive folder named Research Library is suitable; a local folder also works. Then use the toolbar to import PDFs or add a DOI, PMID, arXiv URL, publisher URL, or text. No Apple Developer account is needed for the ad-hoc macOS build.

Minimum deployment targets are macOS 14 and iOS 17. Validation on this machine uses macOS 27.0.1, Swift 6.4 and the macOS 27 SDK. The iOS capture UI is also tested on Simulator 18.5. Other older deployed OS versions have not been tested. Full Xcode 27.0 and its iOS/Simulator 27 SDKs are installed. Both application targets and the embedded Share Extension have been compiled.

## Build and test
From the project directory:

```sh
./Scripts/build-macos.sh
./Scripts/test.sh
./Scripts/build-ios.sh # Simulator app and embedded Share Extension
```

There are no downloaded package dependencies. SQLite is supplied by Apple. The build uses temporary derived storage outside iCloud to avoid Finder/file-provider attributes interfering with code signing. Keep project source downloaded locally when building; a low-disk iCloud workspace can evict source during compilation. The build script assembles and ad-hoc signs the macOS bundle. Tests use Swift Testing and generated legal fixtures; network providers are mocked. macOS file-coordination and Vision services must be accessible to the test process. A restrictive execution sandbox can block these services even when ordinary filesystem access works.

`ResearchLibrary.xcodeproj` contains shared schemes **Research Library**, **Research Library Capture**, and **Research Library Share**. With full Xcode, build the macOS scheme or select an iOS simulator for Capture. Simulator builds can use `CODE_SIGNING_ALLOWED=NO`. Installing on a physical device requires a suitable signing team and the shared application group `group.org.researchlibrary.app`. Signing/distribution is independent of the local macOS application. Project generation is reproducible with `python3 Scripts/generate-project.py`. Select an installed, booted iOS Simulator and use Product → Test on the Capture scheme to run the native capture/persistence UI test. The Debug-only harness uses a generated archive inside that test app; Release builds exclude it.

## Portable archive

```
Metadata/<UUID>.json
PDFs/<ordinary files>
Inbox/<incoming PDFs and captured files>
Inbox/Requests/<UUID>.json
Needs Review/
Exports/
Recovery/<deleted metadata, earlier metadata snapshots, and PDF edit recovery copies>
```

Metadata schema 1 contains normalized authors and ordered authorships, resources, identifiers, dates, tags, collections, favorites, read state, provenance and user notes. JSON dates use ISO8601. UUIDs remain stable when PDFs are renamed or attached later. Unknown object keys are preserved on updates. Unsupported/malformed sidecars are retained and reported rather than overwritten. Every metadata replacement is coordinated and atomic; previous content is retained under Recovery/Metadata. A deleted record's metadata is retained in Recovery; its attachments are retained.

SQLite lives under `~/Library/Application Support/ResearchLibrary/<library-path-hash>/index.sqlite`, never inside the iCloud library. PDF pages, sections, chunks, FTS and Spotlight are derived. PDFs are not database blobs. No extracted full text or embeddings enter authoritative JSON.

## Daily workflows
- **Hot folder:** put PDFs in Inbox while the Mac app is running. Polling waits for stable size/modification time; cloud-only files request a download and retry. The queue survives application termination. After successful processing, the Inbox original is removed only when its saved metadata references a verified organized copy in PDFs. If that copy has since been highlighted, cleanup also verifies the retained original PDF in Recovery/PDFs. Completed captures from earlier versions are cleaned up by the same check. Failed, cancelled, pending-review, changed, or unverifiable files remain in Inbox; cleanup retries after restart. Files outside Inbox are retained. Files already referenced by capture requests are not submitted again by the watcher.
- **URL-only articles:** add a DOI, PMID or URL. Crossref/PubMed/arXiv enrich identifiers. Page access or PDF download failure retains the article and its URL. Authentication failures are recorded; no authentication/paywall bypass is attempted. “PDF unavailable” includes Website and Attach PDF actions.
- **Late attachment:** choose Attach PDF on an item, or drop a PDF containing the matching DOI into Inbox. Exact hashes and high-confidence identifiers attach to an existing record. Ambiguous title/author/year matches prompt Show Existing, Attach to Existing, Keep Both or Cancel. New tags/notes from duplicate captures are retained.
- **Automatic web metadata:** PDF imports extract identifiers from embedded metadata/first pages, using OCR for scanned pages. Without identifiers, an embedded/first-page title can be searched in Crossref; automatic title matches must be unique and exact after normalization, with available year/author checks. Crossref, DataCite (registry fallback), Europe PMC, PubMed, arXiv, and accessible publisher citation/JSON-LD metadata are combined where applicable, including a second pass for newly discovered identifiers. Missing responses do not erase earlier fields. Titles, authors/ORCIDs, abstracts, publication dates, journals, volumes/issues/pages, identifiers, publisher, language, ISSN/ISBN, keywords and licenses are retained when supplied. Full matching provider records are preserved in `sourceMetadata` within each JSON sidecar, including extra funding, affiliation, reference and related-resource fields. Provider keywords are searchable without changing personal tags. **Refresh Web Metadata** fetches available details for existing records while preserving human corrections and notes. Sources can omit fields or be unavailable; ambiguous/unmatched titles stay local and need review.
- **Organization:** Edit Metadata changes authors, year, publication, identifiers, abstract, tags, multiple collections, notes, favorites and read state. Human edits are authoritative. The sidebar filters favorites, unread, recent items, PDF availability, review items, tags and collections. Search includes metadata and PDF body text, supports phrases and multiple terms, and has author/year/journal filters.
- **Source navigation:** body matches show page numbers; Open PDF uses the internal PDFKit viewer at the matching page. Attachments can be revealed in Finder. Supplements and general captured files are retained without executing them.
- **Filenames:** Settings offers `{year}`, `{author}` and `{title}` tokens. The default is `YEAR - FIRST AUTHOR - SHORT TITLE.pdf`. Unsafe characters are removed and collisions are disambiguated. Organize PDF Filenames copies to the new name and atomically updates metadata; the prior file is retained and may be reported as an orphan.
- **Review:** low-confidence items appear in Needs Review. Failed captures have a retry action. The Needs Review filesystem directory is reserved for recovery workflows; review membership is metadata-based, not determined by moving original files into that directory.

## PDF reader

Selecting a paper displays its PDF inside the main library window. The **Metadata** toolbar button shows or hides the article’s metadata, notes and attachment actions in a right-hand sidebar. Metadata follows the active reader tab. Articles without an attached PDF show a PDF-unavailable view with Attach PDF, Website and Show Metadata actions.

The library list stays available beside the PDF; the reader’s **Library** button hides or shows those columns for more space. Normal clicks replace the active PDF instead of adding tabs. Middle-click a paper, or right-click it and choose **Open PDF in Tab**, to keep the current paper and open another tab. Opening a PDF that already has a tab activates that tab. Replacement waits for pending highlights to save and keeps the other open tabs. Middle-click a tab, or click its × button, to close it; closing also waits for pending highlights. **Compare** places two open papers side by side and hides the library columns, giving each PDF its own navigation, search, selection and zoom. Metadata can remain visible while reading or comparing PDFs.

- Navigate with page thumbnails, the PDF’s table of contents, the page-number field, previous/next page buttons, and reading-history buttons. PDFs without an outline show an explanatory message.
- Zoom with the toolbar, fixed percentages, **Fit width**, or **Fit page**. In the PDF, Command-plus/minus changes zoom and Command-0 fits the width. Manual zoom and fit settings are remembered per attachment on this Mac.
- **Find** (Command-F) searches selectable PDF text, lists page-specific results, and moves between matches. Scanned PDFs without a text layer remain searchable through the library’s existing OCR index.
- Select text and press **H**, click **Highlight**, or use the context menu. Highlights support six colors, multiple lines and multiple pages, undo/redo, recoloring and deletion. The annotation sidebar searches text, filters by color, jumps to the marked passage, and displays existing PDF annotations. Only highlights are editable in this release.
- Highlights autosave into the ordinary PDF and remain visible in Preview and other compatible readers. The save status and any errors appear in the toolbar. Each save checks the current file checksum and retains a recovery version under `Recovery/PDFs/<resource-id>/`; a conflicting external edit requires reloading instead of silently overwriting it. Library checksums update with each save, while the original hash remains available for duplicate detection. Closing a tab/window or quitting waits for pending saves.
- Cloud-only PDFs show download progress and open automatically when ready. Selecting another paper cancels an obsolete replacement; explicitly requested tabs can download independently. Already downloaded iCloud versions are readable immediately. Connection errors or downloads still pending after five minutes are reported.
- PDF navigation, page entry, zoom, Find, highlight color, highlight/undo/redo, and save status live in the main window toolbar beside the library search field. In comparison mode, clicking a pane or selecting its text directs the toolbar to that PDF. **Refresh Inbox** (Command-R) in that toolbar checks the hot folder, waits briefly for file stability, processes captures, and refreshes the library without replacing the active PDF. Automatic Inbox monitoring continues as before.
- The toolbar has one **Library** visibility toggle and one **Add to Library** menu for PDF imports or URL/identifier capture. **PDF Navigation** opens thumbnails, contents, Find (Command-F), or highlights. The page-count menu contains first/last page and previous/next reading location; the curved arrow buttons are exclusively highlight undo/redo. **Select Library…** remains in the File menu. The tab bar contains tabs and Compare.
- The last page, zoom mode and sidebar settings are remembered locally by library and attachment. Opening a library search result overrides the remembered page with the matching page.

## iCloud and capture
Chrome users can use the [Save to Research Library Chrome extension](ChromeExtension/README.md). One toolbar click saves a web PDF into the selected library’s Inbox hot folder through a local Mac helper; the app then imports and organizes it. See that guide for one-time setup and the distinction between a saved PDF and a URL-only handoff.

The macOS app also bundles **Save to Research Library** for Safari: use its toolbar button for the current article/PDF URL, or its save button beside individual Google results. Enable it through **Library → Enable Safari Extension…** and follow the [Safari setup guide](Apple/SafariExtension/README.md). The local ad-hoc build requires Safari's **Allow unsigned extensions** option. Captures use the same Inbox and deduplication workflow as imports and Shortcuts.

The selected folder's access is persisted using bookmarks. Files are coordinated and cloud placeholders are materialized before reading. The Mac reconciles sidecar changes while running. Each device maintains its own index. Keep the entire portable folder backed up; iCloud synchronization is not a replacement for backups.

The iOS companion selects the same folder, then captures URL/DOI/PMID/text or files with optional collection/tags/note. Its Share Extension receives Safari URLs, PDFs, files and text. It writes portable IngestionRequests; processing happens when the Mac app is running. The Mac works independently.

The shared **Add to Research Library** App Intent accepts URL, file, text, DOI, PMID, title, collection, comma-separated tags, and note. Choose a library once in the app before background capture. In Shortcuts, receive Safari URLs, optionally Ask for Input for collection/tags/note, and pass them to Add to Research Library. For zero-interaction capture, pass the shared URL/file directly. “Save to Library” App Shortcuts are declared in the app targets. The intent's actual perform method is exercised by automated tests. Xcode builds generate the action, stable entity and localized App Shortcut metadata in the applications. The ordinary Swift-package fallback does not generate this system metadata. Siri invocation, user-created Shortcuts and Share Sheet interactions require on-platform verification.

The ready-to-import macOS shortcut is **Shortcuts/Save to Research Library.shortcut**. Open it and click **Add Shortcut** in Apple's import window. It receives PDFs, article URLs, Safari webpages, or link text from the Share Sheet; it also enables Finder/Services Quick Actions and the Shortcuts menu bar. Running without shared input uses the clipboard. PDFs go to Inbox; links become portable capture requests. The selected library bookmark supplies the destination, so changing libraries does not require editing the shortcut. It invokes the native App Intent without shell scripts. Processing happens when the Mac app is running. macOS may ask for normal app/file access or require enabling Shortcuts in the Share Sheet. Rebuild the file with `python3 Scripts/build-shortcut.py`, then sign it with `shortcuts sign --mode anyone --input 'Shortcuts/Save to Research Library.unsigned.shortcut' --output 'Shortcuts/Save to Research Library.shortcut'`.

For iPhone/iPad, import **Shortcuts/Save to Research Library (iOS).shortcut**. The Mac shortcut references `org.researchlibrary.mac`; the iOS shortcut instead references the companion's `org.researchlibrary.capture` App Intent and omits Mac-only menu bar and Finder surfaces. Install **Research Library Capture** on the device, open it, and choose the same iCloud Drive library folder before running the shortcut. Share a Safari article URL or PDF to **Save to Research Library (iOS)**, or run it with a copied link. Merely syncing the Mac shortcut does not replace its app reference. Generate with `python3 Scripts/build-shortcut.py --platform ios`, then sign with `shortcuts sign --mode anyone --input 'Shortcuts/Save to Research Library (iOS).unsigned.shortcut' --output 'Shortcuts/Save to Research Library (iOS).shortcut'`. The generated action references and signed artifact have been checked; execution on iOS 27 still requires device verification.

## Permanent deletion

Right-click an article, or open its metadata Actions menu, and choose **Delete Permanently…**. Confirm to remove its metadata, managed PDF/supplement attachments, linked Inbox captures, and app recovery copies, including earlier filenames recorded in metadata recovery. Open reader tabs are retired before deletion so autosave or pending downloads cannot recreate the item. Attachments referenced by another current article, external import originals, and previously exported files/backups are retained. The existing **Delete (Keep Recovery Copy)** action remains available.

Permanent deletion uses a coordinated, restart-safe path manifest. An interrupted deletion retries during library reconciliation. Completed manifests retain only the article UUID with empty path/request lists, preventing stale iCloud metadata from restoring the article. This format requires updated apps on other devices to honor deletion markers. Unavailable metadata or unsafe paths cause an error rather than guessing which attachments to remove. This operation cannot be undone within the app.

## Migration and export
Opening a reference without a PDF searches the selected library folder (including its existing PDF subfolders) before looking online. Paperpile attachment filenames and full titles help match local copies; ambiguous matches need review. Online lookup uses exact identifiers with Europe PMC, current PMC Cloud Service version metadata, arXiv, and accessible publisher PDF links. Downloads are checked as readable PDFs and stored directly as one organized copy. Publisher restrictions, unavailable PDFs, uncertain matches, and temporary failures appear in the library and **Needs Review**. **Find PDF Again** retries immediately; automatic failed web lookups have a one-hour cooldown. Existing iCloud placeholders download automatically in the reader.

Use Library → Import Paperpile JSON / BibTeX. Supported JSON forms are an array or an object containing `references`, `items`, or `papers`. Bibliography fields, ordered authors, named labels/folders, notes, identifiers and remote attachment URLs are mapped. Relative attachment `path`/`localPath`/`file` or `pdf` references to exported PDFs next to the bibliography are copied and attached. Absolute/escaping paths are rejected. Paperpile `_id` values provide stable migration identities, so repeated imports merge rather than duplicate records. Paperpile publication dates, URL arrays, citation keys, ORCIDs, and attachment filename hints are supported. Original Paperpile records are retained in portable source metadata. Folder UUIDs without names are retained there rather than displayed as collection names. PDFs are retrieved on demand when opening a paper; importing a bibliography does not download the whole library. Existing notes, manual corrections, attachments, and deletion markers are preserved. Exported PDFs can also be placed in Inbox or manually attached.

Library → Export writes JSON, BibTeX or RIS to Exports without networking. JSON contains the complete normalized records; keep PDFs alongside it. A single schema sidecar can also be reimported for recovery of a deleted item. Import preserves existing human metadata when identifier duplicates exist and merges tags/collections/notes.

## Recovery and diagnostics
Library → Rebuild Local Index reconstructs SQLite, native extraction/OCR, sections, chunks, FTS and Spotlight from sidecars and attachments. Processing must finish before rebuilding. Malformed sidecars and missing PDFs are reported, and valid records continue rebuilding. URL-only items remain valid.

Check Integrity reports missing attachments, broken/escaping paths, duplicate hashes, hash changes, orphan files, malformed JSON and malformed capture requests. It never deletes orphaned files. Reconcile an orphan with Attach PDF/Attach Supplement; restore metadata using Recovery or your backup. Older snapshots can also be inspected with an ordinary JSON editor. Export Diagnostics writes counts, processing states and integrity issues without document text or notes. OSLog categories expose ingestion and Spotlight failures without logging document bodies.

An optional `ResearchLibraryTool` package executable provides `add`, `import`, `search`, `rebuild`, `integrity` and `export` against a supplied folder, using the same services as the app. It is a recovery/testing tool, not a required background server.

## Privacy and network behavior
No PDF, extracted body text or personal notes are uploaded to metadata or AI services. There are no AI calls or embeddings in V1. Metadata lookups send DOI/PMID/PMCID/arXiv identifiers or a candidate bibliographic title when identifiers are absent. Identifier matches must agree; title searches require a unique exact match with available year/author checks. Publisher lookups fetch public landing-page metadata. URL capture retrieves the submitted public page, a directly served PDF, or a publisher-declared `citation_pdf_url`. Scripts from pages/imports are never executed. Networking uses bounded timeouts, identifiable User-Agent, serialized ingestion, response caching, three-second request spacing, HTTP status handling and bounded retry/backoff. Records survive provider failures. Local/private literal network URLs and unsafe path traversal are rejected.

## Current validation limits
Real iCloud propagation, two simultaneous Mac writers, Siri/Share Sheet and Spotlight launch through the system UI, and OS versions beyond those listed above require further on-platform checks. A deterministic 20,000-record benchmark verifies search and pagination; it does not measure a large scanned-PDF collection or iCloud throughput. The app coordinates archive operations and retains metadata snapshots but is not a distributed transaction system. OCR and section recognition are best-effort; extraction failures preserve the item and allow retry. A publisher without a declared accessible PDF remains URL-only. There is no chatbot or semantic index population.
