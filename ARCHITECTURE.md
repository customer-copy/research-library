# Research Library architecture
The authoritative archive is a selected folder containing Metadata, PDFs, Inbox, Needs Review, and Exports. Each UUID JSON sidecar contains bibliographic records, ordered normalized authors, resources, tags, collections, notes, and user edit provenance. Sidecar writes are atomic and coordinated. Unknown JSON fields are merged back on write. Attachments are copied, never moved out of their source during initial ingestion.

Device-local SQLite, extraction pages, sections, deterministic chunks, FTS, and Spotlight are rebuildable. A shared Swift package uses Apple's SQLite C library (no third-party dependency), PDFKit, Vision, CryptoKit, Foundation networking, and structured concurrency. A library actor serializes archive changes and database access. UI state lives on the main actor; the library actor serializes ingestion decisions. Native PDF/OCR and text derivation run in cancellable utility tasks so search and queue-status reads remain available during extraction. Persisted capture requests reside in Inbox/Requests so devices can exchange them without syncing an active database. Stable request IDs double as new item IDs for crash recovery. Metadata enrichment may fail without losing a record.

The environment has Xcode 27.0, Swift 6.4 and macOS/iOS/Simulator 27 SDKs. The Xcode project builds the macOS app, iOS capture app and embedded Share Extension. The scripts package an ad-hoc macOS build and unsigned Simulator build without a developer account; a Swift-package macOS fallback remains available. Physical-device distribution requires signing.

The hot folder polls coordinated directory snapshots and waits for stable size/date before ingestion. Every processing pass validates/downloads cloud files. Invalid/ambiguous captures enter review. Network work is serial, rate limited, bounded and cancellable. Human edits are authoritative. Deleted items move into a recovery archive rather than deleting attachments. Page citations use an internal PDFKit viewer.

## SDK-specific decisions
Swift 6.4 is used in Swift 5 language mode for broad Apple framework compatibility. The macOS 27 SDK declares a new State macro but Command Line Tools omits its SwiftUIMacros plugin. A local ViewState typealias selects the supported State property wrapper explicitly. This does not replace state behavior or require a custom wrapper.

App Intent types live in ResearchCore; each consuming app/extension declares AppIntentsPackage.includedPackages, and AppShortcutsProvider declarations live in the application targets. This follows [Apple's package registration API](https://developer.apple.com/documentation/appintents/appintentspackage). LibraryItemEntity has stable archive UUIDs, IndexedEntity conformance on macOS 15/iOS 18+, and availability-gated SyncableEntity conformance in the installed OS 27 SDK. OS-managed entity synchronization behavior remains unverified across devices; basic capture uses the ordinary entity/query interfaces.

Hot-folder polling (four seconds) is used instead of platform-specific event streams to converge duplicated/missed events and cloud state into one reconciliation path. Input copies remain in Inbox. The queue avoids creating another request for a file already captured. No distributed locking guarantee is claimed for two Macs processing the same cloud queue concurrently. Atomic/coordinated writes, stable request IDs, identifier/hash reconciliation, and retained snapshots reduce the risk without making iCloud a transactional database.

Archive corrections use conflict checks against modification dates and retained snapshots. New automatic enrichment does not overwrite human-edited existing items. Filename organization uses copy/update/retain instead of destructive moves. Missing attachments and malformed records never cause automatic deletion. A malformed capture cannot stop processing other valid requests.

Metadata API references: [Crossref access and etiquette](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/), [NCBI E-Utilities](https://www.ncbi.nlm.nih.gov/books/NBK25501/), and [arXiv API manual](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/api/user-manual.md). No provider contact email is invented; the User-Agent identifies the application. An optional user-configured contact address can be added later.

Search returns bounded pages with global SQL ordering for relevance, title, year or date added. The UI can keep requesting pages without a 500-item total cap. A generation counter refreshes results when metadata or derived text changes without resetting pagination on every hot-folder poll. OCR pins a supported recognition revision and retries CPU/fast recognition when the accurate accelerator model is unavailable.

Regular file imports now persist a commit checkpoint before copying: selected destination, resource UUID, expected content hash, proposed metadata and base-record fingerprint. Replay verifies the existing destination or installs a verified temporary copy without overwriting unrelated bytes. Metadata sidecars are the archive commit point; Inbox originals remain until completion and verified cleanup. Reader saves recognize an identical partially committed write only with a verified original recovery copy. See RELIABILITY.md for recovery guarantees and remaining distributed/cloud limitations.

Cached library presentation follows deletion-tombstone reconciliation and precedes metadata synchronization. Local filesystem revision markers persist in the derived index, avoiding repeated parsing of unchanged sidecars across launches. PDF availability is verified; existing paths alone no longer imply readable bytes. Reader loading and PDF parsing run on workers, with exclusive PDFDocument ownership transferred to the main actor for PDFView use. Signposts and session timing counters support subsequent performance work.

Search runs through a dedicated actor with a read-only WAL connection, independently of the ingestion actor. SQLite progress callbacks interrupt cancelled requests; the UI debounces typing, ignores stale generations and presents metadata previews before deeper matches. Results are grouped by article with stable selection IDs; matching pages load on expansion. See SEARCH.md for execution, ordering and benchmark limits.
